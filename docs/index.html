Pheri Documentation

Pheri is a fast, terminal-based database management TUI (Terminal User Interface) built for MySQL and MariaDB in Go. Designed for developers, database administrators, and DevOps engineers operating over SSH or in local command lines.

⚡
Ultra-Fast Performance: Pheri compiles to a single native binary with zero runtime dependencies. It boots instantly, uses less than 20MB RAM, and handles multi-gigabyte queries effortlessly.

Key Capabilities

🎨 Syntax Highlighting
Tokenized SQL syntax highlighting in real time for keywords, functions, data types, strings, comments, and numbers.
⚡ High-Speed Compressed Export
Dump entire databases into lightweight, compressed .sql.gz archives compatible with any database GUI tool or CLI.
🔍 EXPLAIN Execution Analyzer
Press F5 to visually audit query plans, join types, scanned row estimates, and pinpoint missing indexes or full table scans.
🛡️ Live Process Manager
Monitor running MySQL threads in real-time with F4. Identify stuck queries and terminate rogue connections with a single keystroke.
🏷️ Read-Only & Env Tags
Tag connections as PROD, STAGING, or DEV. Enable strict read-only mode to prevent accidental data modifications on production servers.
✏️ Inline Cell Editing
Directly edit data cells within the terminal grid and save changes directly back to your database tables.

Installation Guide

Choose your preferred installation method below:

Method 1: Pre-Built Binaries (Recommended)

Download cross-compiled static binaries for Linux (x86_64/ARM64), macOS (Intel/Apple Silicon), and Windows from GitHub Releases:

# Download latest Linux release
curl -L -O https://github.com/vickychhetri/pheri/releases/download/v3.0.0/pheri_3.0.0_linux_amd64.tar.gz
tar -xvf pheri_3.0.0_linux_amd64.tar.gz
sudo mv pheri /usr/local/bin/

Method 2: Install via Go CLI

If you have Go 1.18+ installed on your machine:

go install github.com/vickychhetri/pheri@latest

Method 3: Build from Source

git clone https://github.com/vickychhetri/pheri.git
cd pheri
go build -o pheri main.go
./pheri

SQL Editor & Syntax Highlighting

Pheri features a built-in tokenizing parser that provides rich, low-latency syntax highlighting in the terminal window.

Pheri SQL Editor [PROD - ReadOnly]
-- Fetch high-value orders with user details
SELECT o.id, o.order_number, u.email, o.total_amount
FROM orders o
INNER JOIN users u ON o.user_id = u.id
WHERE o.status = 'COMPLETED' AND o.total_amount > 500.00
ORDER BY o.created_at DESC
LIMIT 50;

Compressed Database Export & Import Guide

Pheri exports database dumps directly into lightweight, compressed .sql.gz files. Compression removes excessive whitespace and repetitive SQL text, reducing dump sizes by up to 95% while ensuring 100% compatibility with external database GUI tools and command-line utilities.

💡
Universal Compatibility: Exported .sql.gz files can be imported directly into DBeaver, phpMyAdmin, MySQL Workbench, Navicat, DataGrip, TablePlus, or via terminal command zcat export.sql.gz | mysql -u user -p dbname.

How to Export Database Dumps

⚡ High-Speed Parallel Export (Ctrl+W / F8)
Press Ctrl+W or F8 to dump all database tables, views, procedures, functions, triggers, and events in parallel into a single compressed .sql.gz file.
⚙️ Selective Export Wizard (Ctrl+E)
Press Ctrl+E to pick specific database objects, choose between Compressed .sql.gz, Plain .sql, .csv, or .json formats, and set custom target output paths.

How to Import Backup Files in Pheri

Press F9 or type :import in the bottom command bar to launch the Interactive Database Import Wizard. Pheri automatically detects whether backup files are compressed (.sql.gz) or plain text (.sql) and streams statements safely without syntax errors.

🛡️
Read-Only Guard: If your connection is set to Read-Only Mode, Pheri blocks import operations automatically to protect production database integrity.
Step / Method Action / Feature Description
1. Launch Import Wizard F9 or :import Opens the location picker form pre-filled with candidate backup files in ./export.
2. Location Picker File / Folder Path Input Accepts single .sql / .sql.gz dump files or export directory folders.
3. Permission Confirmation High-Visibility Warning Modal Requires explicit user confirmation before executing any destructive DDL (DROP) or DML (INSERT/UPDATE) statements.
4. Streaming Import Real-time Execution & Log Output Streams statements individually, optimizes session checks, and displays progress in a live terminal viewer.

Type :format or :fmt to auto-format complex SQL queries with capitalized keywords and clean clause line-breaks.

Environment Tags & Read-Only Guard

Prevent disastrous accidental queries on production databases with connection tagging and enforcement rules.

Environment Tags (-env)

  • PROD Prominently renders a bright red border header tag across all terminal panels to remind you that you are on production.
  • STAGING Renders an amber tag for staging/test environments.
  • DEV Default green tag for local development databases.

Read-Only Safeguard (-readonly)

When launching with -readonly or checking Read-Only in the connection screen, Pheri actively parses incoming queries and blocks non-SELECT mutations (DROP, DELETE, UPDATE, ALTER, TRUNCATE, INSERT) prior to sending them to MySQL server.

FAQ & Troubleshooting

Q: Does Pheri support SSH Tunnels?

A: Yes! You can either use standard local SSH port forwarding (e.g. ssh -L 3306:127.0.0.1:3306 user@remote) and connect Pheri to 127.0.0.1:3306, or run Pheri directly inside your remote SSH terminal session.

Q: Where are saved database connections stored?

A: Connection profiles are stored locally in your user home directory at ~/.pheri_connections.json with file permissions restricted to your OS user.

Q: How do I copy query result data to my system clipboard?

A: Press F11 to maximize the result grid, select rows with arrow keys, and press Ctrl+X or Ctrl+P to copy table formatted text or JSON.
